# CameraSystemMockerRestApi

Python mock implementation of the Camera System Integrator API used by CamBot.

## Role in the new prompt-scan setup

This service is intentionally **not** responsible for saved prompts, prompt runs,
Gemini calls, operator priority scores, or the operator action queue.

The new flow is:

```text
client -> RestApi -> CameraSystemMockerRestApi
                  -> Gemini caller / worker
                  -> Postgres operation results + operator queue
```

This mocker only provides:

- source camera metadata
- source camera groups
- snapshot metadata
- frame image bytes

For real app behavior, browser/client code should call the RestApi facade:

```text
/api/camera-system/...
```

The direct nginx route remains useful for debug and for serving frame images:

```text
/camera-system/...
```

## Snapshot/frame URL behavior

`GET /cameras/{cameraId}/snapshot` returns JSON metadata, not image bytes.
The returned `frame.url` points at the frame image resource.

Example shape:

```json
{
  "snapshotId": "snapshot-cam01-00000001",
  "cameraId": "cam01",
  "frame": {
    "frameId": "frame-cam01-00000001-idx-000000",
    "sequenceNumber": 1,
    "capturedAt": "2026-05-16T00:00:00Z",
    "url": "/camera-system/cameras/cam01/frames/frame-cam01-00000001-idx-000000/image",
    "mimeType": "image/jpeg",
    "width": null,
    "height": null,
    "expiresAt": null
  }
}
```

The frame ID is generated by the mocker from:

```text
frame-{cameraId}-{sequenceNumber:08d}-idx-{frameIndex:06d}
```

- `sequenceNumber` increments per camera snapshot request.
- `frameIndex` chooses which mock image file to serve.
- Clients should treat `frameId` as opaque and use `frame.url`.

Frame URL lookup:

```http
GET /cameras/{cameraId}/frames/{frameId}/url
```

Frame image bytes:

```http
GET /cameras/{cameraId}/frames/{frameId}/image
```

The mocker owns the image bytes. CamBot/Postgres should store only frame
reference fields such as `cameraId`, `frameId`, `snapshotId`, `frame.url`,
`capturedAt`, and `mimeType`.

## Environment

`CAMERA_SYSTEM_PUBLIC_BASE_PATH` controls the URL prefix emitted in snapshot
metadata. It defaults to `/camera-system`, matching the nginx public route.

`CAMERA_MOCKER_DATA_ROOT` defaults to `/data/camera-mocker`.

`CAMERA_MOCKER_CONFIG` defaults to `/data/camera-mocker/defaultCameras.json`.
